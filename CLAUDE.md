- Авторские фразы НЕ ТРОГАТЬ: "стоит немного подзаморочиться", "я ведь знаю что вам не охота"

## СИСТЕМА ПАМЯТИ

Три файла, три роли:
- **CLAUDE.md / MEMORY.md** — постоянные правила и факты о проекте и Никите (годы)
- **PLAN.md** — дорожная карта всех задач (месяцы, галочки)
- **.claude/handoff.md** — где мы прямо сейчас, что на следующий шаг, обещания (дни, переписывается)

Тест на "куда класть инфу":
- Через неделю забудем → handoff
- Будем делать следующие 3 месяца → PLAN
- Это про меня/проект **всегда** → MEMORY

Команды:
- `/morning` — читает handoff, показывает где остановились
- `/endday` — обновляет handoff по итогам сессии

Правила:
- Новый постоянный факт (привычки, правила, люди) → MEMORY.md
- Разовая правка от Никиты по стилю → memory/feedback_тема.md
- Новая задача на проект → PLAN.md
- На чём остановились / что завтра → handoff.md (через /endday)

При старте сессии: читай MEMORY.md (короткий индекс, всегда в контексте) и запусти `/morning` если Никита не сказал иначе.

Handoff-флоу — референс в [references/competitor-guide-aizdec-memory.md](references/competitor-guide-aizdec-memory.md). Папка `memory/YYYY-MM-DD.md` больше не создаётся — её заменил handoff.

## ЛИЧНАЯ БАЗА ЗНАНИЙ НИКИТЫ (knowledge-base/)

Путь: `~/Documents/Projects/knowledge-base/`

Это личный склад знаний Никиты по темам (AI, промптинг, Claude Code, Wispr, маркетинг, бизнес). Отдельный проект, не часть baza-znaniy. Питает все публичные проекты Никиты: этот сайт, контент-завод, стартер-пак.

### Структура
- `raw/` — сырьё (статьи, выжимки, скриншоты)
- `wiki/` — упорядоченные заметки, один файл = одна тема
- `outputs/` — применения знаний к задачам
- `INBOX.md` — быстрые заметки на разбор
- `CLAUDE.md` — правила организации (schema)

### Когда использовать в работе над baza-znaniy

Перед написанием нового блока / секции / статьи — **проверь wiki/** на релевантные темы:
```
ls ~/Documents/Projects/knowledge-base/wiki/
```
Если нашёл подходящий файл — используй его как основу и источник формулировок. Цитируй Никиту буквально, он там пишет от первого лица как любит.

Если файла нет — не блокируй работу, делай блок на основе разговора. После публикации ПРЕДЛОЖИ записать ключевые тезисы в wiki/ для будущего.

### Триггеры для записи в wiki/

Когда Никита говорит (варианты формулировок):
- "Запиши это в вики"
- "Сохрани в базу"
- "В вики"
- "Зафиксируй это"

→ Записываю в `~/Documents/Projects/knowledge-base/wiki/тема.md` по правилам wiki (см. CLAUDE.md в knowledge-base).

Если тема уже есть в wiki — дописываю в существующий файл, не создаю новый.

### Когда предлагать записать сам

Если в разговоре Никита формулирует инсайт / принимает решение / находит фишку — предлагай: **"Хочешь я это зафиксирую в wiki?"**. Коротко, не настойчиво. Он скажет да/нет.

Признаки что стоит предложить:
- Никита что-то узнал впервые и явно обрадовался ("а, так вот как это работает")
- Принято решение которое будет применяться дальше ("теперь всегда делаем X")
- Найдена фишка / трюк / workaround с конкретной пользой
- Никита переформулировал мысль своими словами — это готовый материал для заметки
