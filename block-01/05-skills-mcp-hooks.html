Скиллы, MCP и хуки

По умолчанию Claude Code умеет читать файлы, писать код, запускать команды в терминале. Это уже много. Но настоящая мощь начинается когда подключаешь расширения.

Расширений три вида. Скиллы — это папки с инструкциями: говоришь Claude как вести себя в конкретной задаче. MCP — это внешние инструменты: подключаешь браузер, поиск в интернете, базы данных. Хуки — это автоматические действия на события: например, звук когда Claude закончил думать и ждёт тебя.

Скиллы — инструкции под задачу

Скилл — это папка с файлом SKILL.md внутри. В начале файла YAML-шапка с двумя полями: name (имя скилла) и description (описание что делает и когда применять). Ниже — тело с самими инструкциями.

При старте каждой сессии Claude сканирует описания всех установленных скиллов. Когда ты пишешь задачу — он сверяет её с этими описаниями и решает: нужно ли загрузить какой-то скилл. Если совпадение найдено — тело скилла подгружается и Claude следует инструкциям внутри.

Ключевой момент: тело скилла грузится только когда нужно. В контексте постоянно висят только короткие описания — по строчке на каждый скилл. Это значит, что можно держать десятки скиллов и почти не тратить токены.

▸ YAML-шапка скилла — пример
---
name: frontend-design
description: Use when creating UI components, pages, or visual interfaces.
  Creates distinctive, production-grade frontends. Triggers: "create page",
  "design component", "build interface".
---

Чем точнее описание — тем надёжнее срабатывание. Хорошее описание говорит что делает скилл, что не делает, и какие фразы его вызывают.

Аналогия

Скилл — это как стажёр с инструкцией. Инструкция в кармане (не читает постоянно), достаёт только когда задача подходит под его специализацию.

Где брать скиллы

Есть три источника. Первый — skills.sh, каталог от сообщества. Устанавливаешь одной командой в терминале через npx skills. Второй — официальный маркетплейс /plugins прямо внутри Claude Code: набираешь команду и видишь 100+ плагинов от разных авторов. Третий — скилл-креатор: мета-скилл, который создаёт новые скиллы по документации или промпту. Нужно что-то специфическое — описываешь, он делает.

▸ Терминал — установка и управление
# Установить скилл из каталога
npx skills add anthropics/skills -a claude-code

# Посмотреть установленные скиллы
npx skills ls

# Обновить
npx skills update

Перед установкой незнакомого скилла — проверь источник. Ставь только из проверенных репозиториев: Anthropic, GitHub, Microsoft и других крупных компаний, или скиллы с пометкой о прохождении аудита на skills.sh. Скилл — это инструкции которые выполняет Claude в твоём проекте, поэтому к источнику стоит относиться так же как к любому коду из интернета.

Глобальные vs проектные скиллы

Скиллы можно ставить в двух местах. Глобально — в ~/.claude/skills/. Такие скиллы работают во всех проектах на твоей машине. Проектно — в .claude/skills/ внутри конкретной папки с проектом. Работают только в этом проекте.

Правило простое: общие инструменты и методологии — глобально. Всё что завязано на конкретный продукт, голос, стиль — только в проекте.

Например: скилл для работы с PDF или создания презентаций — глобально, пригодится везде. Скилл с твоими авторскими фразами и стилем для контент-проекта — только в том проекте, в других он будет мешать.

MCP — внешние инструменты через USB

MCP расшифровывается как Model Context Protocol. Это стандарт, который Anthropic разработал чтобы внешние сервисы могли подключаться к Claude единым способом.

Аналогия: Claude Code — это компьютер, MCP — USB-хаб. Каждый MCP-сервер — это адаптер к какому-то сервису: браузеру, базе данных, Google Sheets, системе поиска. Без MCP Claude знает только то, что лежит в папке проекта. С MCP — может искать в интернете, открывать сайты, читать твой календарь, делать запросы к внешним API.

Технически это работает так: каждый MCP-сервер публикует список инструментов с описанием. Claude видит их как обычные инструменты рядом со своими встроенными и сам решает когда какой вызвать — как хороший сотрудник, который знает для чего у него есть каждый инструмент.

Установка MCP тремя способами

Первый — просто попросить Claude. Пишешь в чат: «Установи MCP сервер для поиска Exa» — он сам найдёт нужный пакет, скачает и настроит конфиг. Самый простой путь для большинства серверов.

Второй — команда в терминале напрямую:

▸ Терминал
claude mcp install exa

Третий — визуальный каталог Smithery. Заходишь на сайт, находишь нужный MCP-сервер, жмёшь кнопку установки — он сам генерирует команду и объясняет что делать. Удобно когда хочешь сначала посмотреть что вообще есть.

MCP или скилл: как выбрать

Частый вопрос: у меня есть задача — ставить MCP или скилл? Ответ зависит от одного: как часто ты это используешь.

MCP
Если используешь часто
Подключается один раз, всегда доступен. Занимает ~2000 токенов контекста постоянно. Например: браузер, поиск в интернете.
Скилл
Если используешь редко
Загружается только когда нужен — не ест контекст постоянно. Например: создание слайдов, работа с PDF.

MCP всегда присутствует в контексте и готов ответить моментально — но за это платишь токенами при каждом запуске. Скилл не стоит ничего пока не нужен. Поэтому частые инструменты — MCP, редкие — скилл.

Три MCP с которых начать

Название Что делает Как поставить
Exa Лучший поиск в интернете. 1000 запросов в месяц бесплатно claude mcp install exa
Context7 Актуальная документация любой библиотеки прямо в чате claude mcp install context7
Chrome DevTools Управление браузером: открыть сайт, кликнуть, проверить через Smithery

Exa заменяет гугление — Claude сам ищет когда нужна актуальная информация. Context7 решает проблему устаревшей документации в обучающих данных: когда пишешь код с новой библиотекой, Claude смотрит живую документацию, а не то что знал год назад. Chrome DevTools нужен если хочешь тестировать сайты или автоматизировать браузер.

Хуки — действия на автомате

Хуки — это shell-команды, которые Claude Code запускает автоматически при определённых событиях. Настраиваются в файле ~/.claude/settings.json в секции "hooks".

Самое полезное применение — звуковое уведомление когда Claude заканчивает задачу. Поставил задачу, ушёл делать другое — услышал звук, вернулся, всё готово. Не надо периодически посматривать на экран.

▸ ~/.claude/settings.json — добавить секцию hooks
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "afplay /System/Library/Sounds/Glass.aiff >/dev/null 2>&1 &"
          }
        ]
      }
    ],
    "Notification": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "afplay /System/Library/Sounds/Glass.aiff >/dev/null 2>&1 &"
          }
        ]
      }
    ]
  }
}

Событие Stop срабатывает когда Claude закончил отвечать. Событие Notification — когда Claude ждёт твоего разрешения на какое-то действие. afplay — это встроенная macOS-утилита для воспроизведения звука, ничего устанавливать не нужно. /System/Library/Sounds/Glass.aiff — системный звук «Glass», короткий и не раздражает. Хвост >/dev/null 2>&1 & запускает команду в фоне чтобы не блокировать и не мусорить в вывод.

После сохранения файла изменения вступают в силу сразу — перезапускать Claude Code не нужно.

Личное
