CLAUDE.md — память проекта

Каждый раз, когда открываешь новый чат в Claude Code, он не помнит ничего. Не знает, что за проект. Не знает, какой стиль ты выбрал. Не знает правила, о которых вы договорились в прошлый раз. Начинает с чистого листа.

CLAUDE.md решает эту проблему. Это файл в корне проекта, который Claude читает автоматически при каждом запуске — ещё до того, как ты написал хоть слово. Один раз настроил, и больше не нужно объяснять с нуля.

Как это работает

CLAUDE.md — это как памятка для нового сотрудника на холодильнике: «У нас принято так-то. Вот чего нельзя делать. Вот на что обращать внимание». Любой новый чат — и Claude сразу в контексте.

Как создать

Есть два способа. Самый простой — попросить Claude сделать это за тебя. Пишешь в чат одну команду и он сам изучит структуру проекта и сгенерирует файл под неё:

▸ Терминал
/init

Claude пройдётся по всем файлам в папке, поймёт что за проект, и создаст CLAUDE.md с базовой структурой. Потом ты просто дополняешь под себя.

Второй способ — создать руками. Файл называется ровно CLAUDE.md и лежит в корне проекта, рядом с остальными файлами.

Что писать внутри

Хороший CLAUDE.md отвечает на пять вопросов: что за проект, для кого, какой стек, какие правила работы, и чего нельзя делать. Вот рабочий шаблон:

▸ CLAUDE.md — шаблон для старта
# Название проекта

## Что это
Одно-два предложения: суть проекта и для кого.

## Стек
- Язык / фреймворк
- Хостинг
- Особые ограничения (без внешних библиотек, только ES6 и т.д.)

## Правила работы
- Перед созданием нового файла — сначала скажи что планируешь
- Не удаляй файлы без явного подтверждения
- Перед фиксом бага ищи корневую причину, не заплатку

## Стиль
- Тёмный фон, оранжевый акцент
- Короткие абзацы, простой язык
Важно

Держи файл коротким. Идеально — до 100 строк. Чем длиннее CLAUDE.md, тем больше токенов он занимает при каждом запуске сессии. Длинный файл = меньше места для реальной работы в контексте.

Три правила, которые реально работают

Из практики — три инструкции, которые меняют качество работы сильнее всего. Добавь их в свой CLAUDE.md:

▸ Добавить в CLAUDE.md
## Правила поведения

1. Если считаешь, что моё решение неоптимально — скажи об этом.
   Оспаривай мои идеи, если видишь лучший способ.

2. После каждой задачи структурируй ответ так:
   - Что сделано
   - Что требуется от меня (если нужно)
   - Следующий шаг

3. После выполнения задачи предлагай улучшения, которые
   заметил по ходу работы.

Первое правило даёт тебе партнёра, а не исполнителя — Claude будет указывать на ошибки, а не молча делать как сказано. Второе убирает хаос из ответов — всегда понимаешь, что сделано и что дальше. Третье постепенно улучшает проект без отдельных задач на «проверь всё».

Уровни автономности

Одна из самых полезных вещей, которую можно добавить в CLAUDE.md — явные правила что Claude делает сам, а что ждёт твоего разрешения. Без этого либо постоянные окна с вопросами, либо Claude делает всё без спроса — включая то, что лучше бы подтвердить.

✓
GREEN — делай сам
Чтение файлов, поиск, git commit / log / diff, npm install, создание папок, запись в memory/
!
YELLOW — делай, но покажи
Создание новых файлов, правка трёх и более файлов за раз, обновление MEMORY.md
✕
RED — стоп, жди
rm -rf, git push / reset --hard, любой деплой, DROP TABLE, операции с деньгами

Добавь это в CLAUDE.md адаптировав под свой проект. Конкретный список команд работает лучше, чем расплывчатое «спрашивай перед опасными действиями».

Папка .claude/rules/

Когда правил становится много, держать их все в одном CLAUDE.md неудобно. Решение — вынести отдельные блоки в папку .claude/rules/ в отдельные файлы:

▸ Структура
.claude/
  rules/
    autonomy-levels.md   ← GREEN / YELLOW / RED
    code-style.md        ← правила форматирования кода
    git-workflow.md      ← как коммитить, как пушить

Основной CLAUDE.md остаётся коротким и ссылается на эти файлы. Claude подхватывает их автоматически.

AutoMemory — ещё один слой

Помимо CLAUDE.md в Claude Code есть встроенная AutoMemory — функция, при которой Claude сам записывает заметки о проекте и твоих предпочтениях по ходу работы. Это работает параллельно с CLAUDE.md и не требует твоего участия.

Посмотреть что там сохранилось, включить или выключить — команда:

▸ В чате Claude Code
/memory

Минус AutoMemory — она пишет всё подряд, иногда не самое нужное. Полезно иногда заходить и чистить лишнее руками.

settings.json и settings.local.json

В папке .claude/ могут лежать два файла с похожими именами, и важно понимать разницу:

Файл Для чего Коммитить?
settings.json Общие настройки проекта — разрешения, хуки, параметры. Одинаковые для всей команды Да
settings.local.json Личные настройки твоей машины — bypass permissions и т.д. Только для тебя Нет — в .gitignore

.gitignore — это файл, который говорит git какие файлы не пушить в репозиторий. Нужен чтобы случайно не залить в интернет пароли, ключи API и личные настройки. Claude Code при первом запуске сам добавляет туда .claude/settings.local.json — так что об этом можно не беспокоиться. Подробно про .gitignore и что туда нужно добавить разберём в статье про GitHub.

Итого

CLAUDE.md + .claude/rules/ + settings.json — это три файла, которые превращают каждый новый чат в продолжение, а не начало с нуля. Потрать час на настройку один раз — сэкономишь часы объяснений потом.
