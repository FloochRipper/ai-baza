### 08 — Контекстное окно: почему Claude тупит 📝 *(новая)*
*Сюда же: Graphify и оптимизация токенов*
- Что такое контекстное окно (оперативная память агента)
- Зелёная (0–50%) / оранжевая (50–70%) / красная (70–85%) зоны
- «Lost in middle» — почему середина разговора теряется
- Автокомпакт на 85% — что происходит автоматически
- /compact с аргументом — ручное сжатие с указанием что сохранить
- /clear — полная очистка, новый старт
- Rewind (двойной Escape / /rewind) — откат переписки И файлов
- Statusline — видеть % заполнения прямо в терминале
- Правила: одна задача = одна сессия; декомпозиция; не раздувать инструменты
- Модели: Opus (сложные задачи), Sonnet (рабочая лошадь), Haiku (дёшево и быстро)
- **Graphify и «карта файлов»:** что это, когда реально помогает (52+ файлов кода), когда не нужно (контентные и небольшие проекты); почему CLAUDE.md < 100 строк решает ту же проблему проще

### 09 — Второй мозг: Claude который всё помнит 📝 *(новая)*

Кто читает: все — и новички, и те кто уже работает с Claude Code. Одна из самых практичных статей.

**Что это такое и зачем**
- «Второй мозг» — система где знания хранятся и используются, а не просто лежат
- Разница с Obsidian: тот только для глаз, наш Claude активно работает с этими знаниями
- Что мешает без второго мозга: Клод не помнит прошлые сессии, каждый раз объяснять заново

**Три слоя системы — объяснение и настройка каждого**

Слой 1 — AutoMemory (встроенный, сам пишет)
- Что это: Claude сам сохраняет заметки о тебе, проекте, предпочтениях
- Как включить/выключить: команда `/memory` → список + переключатель
- Где хранится: `.claude/` папка проекта
- Минус: пишет всё подряд, иногда не то; можно редактировать руками

Слой 2 — Папка memory/ (управляемая, ты решаешь что важно)
- Структура: `memory/user.md`, `memory/feedback.md`, `memory/project.md`
- Индекс MEMORY.md — одна строка на каждую заметку, Claude читает его первым
- Команды для настройки:
  ```bash
  mkdir -p .claude/memory
  touch MEMORY.md
  ```
- Как попросить Claude сохранить что-то: «запомни, что я предпочитаю краткие ответы»
- Как выглядит правильный файл памяти (пример структуры)

Слой 3 — knowledge-base/ (общий склад, работает во всех проектах)
- Структура: `wiki/` (по темам), `outputs/` (датированные разборы), `raw/` (сырьё), `INBOX.md`
- Команды для создания с нуля:
  ```bash
  mkdir -p knowledge-base/{wiki,outputs,raw}
  touch knowledge-base/INBOX.md
  ```
- Как работает INBOX: быстрая запись → раз в неделю Claude раскладывает по папкам
- Тест «куда класть»: через неделю забудешь → handoff; останется актуальным месяцы → wiki; про тебя лично → memory

**Непрерывность между сессиями — handoff**
- Файл `.claude/handoff.md` — где остановились, что обещали, что следующее
- Команда `/morning` — начать сессию: Claude читает handoff и докладывает
- Команда `/endday` — закончить: Claude обновляет handoff по итогам чата
- Как создать handoff:
  ```bash
  touch .claude/handoff.md
  ```
  Затем попросить: «запиши в handoff что мы сегодня сделали»

**Итоговая схема: что куда идёт**
- Разбор инструмента / решение → outputs/ с датой
- Универсальная методология → wiki/
- Про тебя и твои привычки → memory/
- Текущая задача → handoff.md

**Что НЕ нужно**
- Obsidian — это просто редактор markdown-файлов, не нужен
- Graphify — для кодовых репозиториев, не для этого
