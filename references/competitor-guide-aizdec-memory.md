# Референс aizdec — Система памяти агента

## Что у конкурента (главные идеи из урока)

Четыре вида памяти с чётким разделением ролей:

| Вид | Вопрос | Кто пишет |
|-|-|-|
| CLAUDE.md | Как работать с этим проектом? | Ты |
| Skills | Как выполнять конкретные задачи? | Ты |
| MEMORY.md | Что я уже знаю об этом проекте? | Агент сам |
| handoff.md | Где мы щас и чё делаем? | Ты (или по команде) |

**Ключевые тезисы:**

1. **MEMORY.md = индекс (до 200 строк), детали - в отдельных файлах** которые Claude подгружает по необходимости. Без чистки превращается в свалку.

2. **@import в CLAUDE.md** - можно ссылаться на другие файлы: `@docs/api-rules.md`. Рекурсивно до 5 уровней.

3. **`.claude/rules/`** - модульные правила по темам (api-style.md, testing.md, security.md). Подхватываются автоматически. С frontmatter `paths: ["src/api/**/*.ts"]` применяются точечно к нужным файлам.

4. **Handoff = передача смены.** Файл `.claude/handoff.md` с разделами:
   - На завтра
   - Сделано
   - Обещания
   - (опц.) Планируется

5. **Handoff встраивается в команды** `/morning` и `/endday` - тогда обновляется автоматически, не надо вручную.

6. **Context rot** (термин Anthropic): чем больше в контексте, тем хуже модель вспоминает конкретику. *"3 строчки точных правил > 3 страницы размытых пожеланий."*

7. **Сжатие `/compact`** - можно с фокусом: `/compact сосредоточься на работе с API`.

8. **Три принципа хорошей памяти:**
   - Разделяй что пишешь ты и что пишет агент
   - Чисти регулярно ("раз в неделю: Claude, почисти устаревшее")
   - Конкретика побеждает объём

9. **Хуки** - для автоматизации handoff (отдельный урок у конкурента, пока не парсили).

## Наш разбор: три файла - три роли

Разобрались что `PLAN.md` / `handoff.md` / `MEMORY.md` не дублируются а дополняют.

| Файл | Отвечает на вопрос | Горизонт | Обновление | Пример |
|-|-|-|-|-|
| **PLAN.md** | Что вообще надо сделать в проекте? | Месяцы | Медленно, галочками | "Доделать блок 1, подключить Netlify, трипвайер" |
| **handoff.md** | Где мы прямо сейчас? | Дни / неделя | Каждая сессия, переписывается | "Остановились на Установке. Завтра Тарифы. До пятницы Диме промпты" |
| **MEMORY.md** | Что я должен знать о Никите и проекте всегда? | Годы | По факту появления | "Короткое тире не длинное. Запрещённые слова: погружение, на стыке" |

**Тест на куда класть информацию:**
- Через неделю забудем → handoff
- Будем делать следующие 3 месяца → PLAN
- Это про меня/проект **всегда** → MEMORY

**Примеры:**
- "не люблю эмодзи" → MEMORY (факт навсегда)
- "до пятницы отправить Диме промпты" → handoff (разовое, краткосрочное)
- "сделать раздел про тарифы" → PLAN (задача)
- "Instagram @nikitashlyk" → MEMORY (факт)
- Дима как постоянный клиент → MEMORY, его текущий запрос → handoff

## Нюансы работы handoff

**Про несколько вкладок:** каждая вкладка/окно Claude Code = отдельная сессия со своим контекстом. Файл handoff.md на диске - один, его видят все сессии. Но `/endday` в одной вкладке запишет только то что делали в ней. При параллельной работе - делать `/endday` в каждой вкладке, они допишут свои куски.

**Про команды vs голосом:** команды это просто ярлыки. `/endday` = написать вручную "обнови handoff: что сделали, на завтра, обещания". Команды нужны чтоб не забывать и не лениться, плюс в них можно зашить нюансы (например "всегда показывай мне обновление перед сохранением").

## Что из этого брать в свою базу знаний

**Высокая ценность (точно брать):**

1. **Handoff как концепт** - три раздела (сейчас работаем / следующим шагом / обещания). Проще и точнее чем дневные файлы `memory/YYYY-MM-DD.md`.
2. **Команды `/morning` и `/endday`** - автоматизируют обновление handoff.
3. **Context rot как принцип** - "конкретика побеждает объём", важная философия написания CLAUDE.md.
4. **@import в CLAUDE.md** - когда файл станет толстым.
5. **`.claude/rules/`** - когда правил накопится на несколько тем.

**Уже есть у нас:**

- Разделение типов памяти (user / feedback / project / reference) - в глобальном промпте Claude это уже есть.
- MEMORY.md как индекс - уже так работает.

**Не брать / переосмыслить:**

- Именование "handoff" - можно оставить или перевести. Варианты: *handoff* (англ), *передача смены*, *журнал*, *сменка*.
- Структура разделов - можно адаптировать под свой флоу. Например добавить "Заметки / открытые вопросы".

## Как переписывать в свой голос (когда будем делать раздел)

- Убрать англицизмы где можно, но "handoff" и "context rot" оставить как термины (они устоялись)
- Не копировать формулировки Тома ("братишка" - его фишка, не твоя)
- Авторская фишка Никиты - показывать на личном примере из этого самого проекта baza-znaniy: "вот у меня есть PLAN, handoff и MEMORY, работают так..."
- Скрин handoff.md из реальной работы = сильнее чем абстрактный пример
- Запрещённые слова: погружение, на стыке, уникальная методика - не использовать
- Тон разговорный, короткие абзацы, короткое тире
